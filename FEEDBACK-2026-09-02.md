# Feedback from the wovim session, 2026-09-02

Context: evaluating winze as the decision record for `~/Documents/germline`,
a method-and-template repo whose durable artifacts are executable laws, an
enumerated boundary, a recorded corpus, and a decision record, with code
regenerated from them. Read `README.md`, `corpus/schema.go`,
`docs/decisions.md`, `docs/typed-citation.md`, `docs/agent.md`,
`docs/onsetter-integration.md`, `docs/metabolism.md` (grep), `cmd/agent/init.go`
and `cmd/agent/mcp.go` (grep), `script/reset-corpus.sh`, and the live
`publicai-memory` store's `memory.go`. Ran no winze binary. Every "winze
can't" below means "the parts I read don't say it can."

Verdict first: winze is the right home for the decision record and beats
both YAML-frontmattered markdown and docmgr for it. The items below are what
stood between that verdict and a conversion.

## 1. Typed citation stops at the module boundary

`CodeRef.Symbol any` is checked by `go build` only when the store and the
cited code are one module. `docs/agent.md` makes a store its own module by
design, many repos to one store, and names deriving a store from the working
directory as the fragmentation to avoid. So the doc→code citation, the
primitive the README puts under everything, cannot reach any repo the store
serves without the store `require`-ing that repo, and cannot reach non-Go
code at all. For germline that means a decision cannot cite the law it
constrains by value; for the wovim pilot it cannot cite a C symbol.

This is also README known-problem 5 ("prose claims about external
dependencies rot with nothing checking them") in mechanical form. Two
requests, either would do:

- **`winze-lint --clients <repo>...`** (or a `clients` file in the store,
  since a store does not know who names it): resolve every `CodeRef.Path`
  string against the client repos' packages with `go/packages` and report
  dangling ones. CI-time rather than compile-time, but the checker is a
  program and the reference cannot rot silently.
- **A content-hashed span ref** for non-Go targets: `Path: "src/nvim/register.c:713"`
  plus a hash of the cited line or span, checked by lint against the client
  checkout. defn already does file-level staleness; this is the same idea at
  span grain.

## 2. `winze-agent init --link` sets the store but not the MCP server

`--link` writes `git config winze.store`. The MCP registration lives in
`~/.claude.json` under specific project paths (four winze checkouts today),
so a repo that links a store still has no `winze_remember` tool in its
sessions until someone registers the server for that path. Request: `--link`
also runs the registration for the current project (or prints the one
`claude mcp add` line), and `docs/agent.md` says which scope it uses. This is
the first thing a new adopter hits and the doc does not mention it.

## 3. Two shapes for "decision"

`corpus/schema.go:37` declares `Decision{ID, Title, Rationale}` alongside
`FailureMode`, `Mitigation`, `OpenQuestion`, and `init` copies them into every
store. `docs/decisions.md` says a decision is not a separate category, it is a
memory with a `Supersedes` lifecycle, and `winze_remember` defaults to
`Concept`. I read `schema.go` first and designed around the struct. Request:
either mark the four bootstrap-era record types as legacy in their comments
with a pointer to `docs/decisions.md`, or give `winze_remember` a
`--role Decision` that writes the typed record so the two shapes converge.

Same file, `Mitigation.Automated`: the comment says an automated mitigation
"runs as a winze lint rule." If that is live, it is exactly the laws hook a
method like germline's wants and deserves a doc; if it is aspirational, the
comment should say so, because it reads as a measurement.

## 4. The dated-measurement lint the README asks for

Known-problem 5 asks for "a lint rule flagging measurement-shaped prose
carrying no date." A first cut that would have caught the `internal/defndb`
case: flag any `Brief`, `Rationale`, or `Quote` that matches
`\b\d+(\.\d+)?\s*(ms|s|KLOC|lines|%|stars|commits|MB|GB)\b` or
`\b(currently|now|is backed by|links in|takes)\b` and has no ISO date within
the same string. Same rule at write time as an onsetter ask on `memory.go`
with `when:` the measurement regex and `not:` the date regex, so it fires
before the claim lands rather than at the next lint run.

## 5. A generic markdown projection per predicate

`--decisions` projects the `Supersedes` graph to text and `winze-okf` projects
the whole store. Germline wants one more projection: a hand-readable list of
one predicate's claims, so `BOUNDARY.md` (declined promises, one reason each)
can be generated from the store rather than maintained beside it. Something
like `winze-query --predicate DeclinesToPromise --md .`. Low priority; it may
be germline's tool to write.

## 6. `init` cannot find its own schema after `go install`

Hit live, 2026-09-02, from `~/Documents/germline`:

```
winze-agent init ~/Documents/germline-memory --private --link
init: no winze corpus found (looked in /home/gas6amus/go/corpus) — set $WINZE_SRC to a winze checkout or pass --from
```

The fallback is "the `corpus/` beside the running binary," and a binary in
`~/go/bin` never has one. `docs/agent.md` explains why the schema is not
embedded (a second copy is the drift the build gate prevents), which is
right, and the fix is a better search: try `go list -m -f '{{.Dir}}'
github.com/justinstimatze/winze` from the module cache, or the checkout the
binary was built from via `debug.ReadBuildInfo` and `vcs.*` settings, before
giving up. Passing `--from ~/Documents/winze` worked; the message is good and
the default is the only thing wrong.

## 7. Stale binary looked like a bug for one call

`winze-add --conjecture --predicate Supersedes --subject A --object B` failed
the build gate with "cannot use A (variable of struct type Concept) as
*Entity value," which `docs/decisions.md` says is auto-resolved. It is:
commit 63b8cee on 2026-08-28 added it, and `~/go/bin/winze-add` was built
2026-08-22. Explicit `.Entity` worked. Not a bug. A one-line
"binary is older than the checkout you pointed `--from` at" warning from
`winze-agent init`, which already knows both paths, would have saved the
round-trip; the doc-versus-binary gap is the same drift the build gate
exists for, one level up.

## 8. Doc nit

`README.md` "Your domain in 5 minutes" says run `script/reset-corpus.sh`, then
"Open `starter.go`". The script `cd`s into `corpus/` and creates the file
there, so the path is `corpus/starter.go`, and it does not exist until the
script has run. One word in the README.

## What I did not find a problem with

Store-per-team resolution order, the sealed `Attribution` with `Conjecture`
carrying no `Quote`, onsetter gating `winze_remember`, metabolism being
scheduler-driven and therefore off for a decision-only store, and the
`Supersedes` chain as the decision lifecycle. Those are the reasons germline
is converting to it.
